# C2000 Pro 适配架构与验证记录

## 1. 分层

```text
ViewModel / View
      │
      ▼
IDeviceApi（页面与协议解耦）
      │
      ├─ RouterApi ───── NRadioLegacyAdapter ── RouterClient(Digest)
      │
      └─ C2000CompatibilityApi
              │
              ▼
         C2000ProAdapter
          ├─ C2000ProClient（Cookie/HTTP）
          ├─ runtime/cellinfo JSON
          ├─ LuCI CBI 页面读取
          └─ 写后回读/写互斥
```

`DeviceConnector` 只访问用户配置的地址，先用公开登录页指纹判断：

- 页面包含 `luci_password` / NRadio 静态资源 → C2000 Pro。
- 否则保留 NRadio Digest 路径。

设备的原始 HTTP 请求只在 Adapter/Client 内出现，ViewModel 不拼接 URL。

## 2. 连接和稳定性

- 客户端强制 `UseProxy=false`，局域网请求不受系统代理影响。
- 登录先取页面、再提交固定 root 表单，最后用受保护接口复核。
- 403/401 会话才会触发一次重新登录。
- JSON 请求不会无限重试。
- 写请求遇到会话失效不会自动重放，避免重复切卡/重启/锁频。
- C2000 写操作共用一个信号量，禁止并发提交。
- 800 ms 短缓存合并同一轮多个页面读取，减少重复请求。
- 轮询使用已有 `_pollGate`，上一轮未结束时跳过。

## 3. 数据口径

- 设备计数器：`cpe.download/upload/device_traffic`。
- 本机速率：对设备计数器按本地单调时钟差分。
- 信号趋势：本机采样 RSRP，缺失/断连保留缺口。
- 终端上线/离线：设备列表本地轮询差分；新终端立即记录，消失连续 2 次才判定离线。
- 所有事件写入统一 `ActivityLog`，并明确写“本地检测时间”。

## 4. 写操作安全流程

所有 C2000 写入口遵循：

1. 读取当前页面/状态。
2. 显示操作对象和风险。
3. 第一次确认。
4. 高风险操作第二次最终确认。
5. 保留原厂完整表单字段并只覆盖目标字段。
6. 提交 HTTP 请求。
7. 检查设备 JSON/CBI 响应，拒绝把 HTTP 200 当成功。
8. 轮询回读设备状态。
9. 回读一致才返回成功；否则“结果待确认”。
10. 记录脱敏操作日志。

## 5. 自动验证

### 离线

```powershell
SelfTest.exe --offline
```

覆盖：

- 错误密码被拒绝。
- Cookie 过期后重建会话。
- 404、500、超时映射。
- 字符串/数字混合字段解析。
- 运行时候选字段、设备身份、蜂窝、终端。
- 锁频页当前/邻居/锁定标记。
- 旧版默认设置迁移。
- 信号历史保存。

UI：

```powershell
dotnet NRadioManager.dll --ui-smoke
```

覆盖 16 个页面、两种尺寸、深浅主题、数据绑定、图表和日志。

### 真机只读

已执行：

```powershell
SelfTest.exe http://192.168.66.1 root --c2000
dotnet NRadioManager.dll --ui-smoke --live
```

结果见交付报告。写操作没有执行。

## 6. 发布

Release 采用 `win-x64` framework-dependent 发布，目标机器需安装 .NET 10 Desktop Runtime。

发布目录会包含：

- 主程序及 DLL
- `ui-smoke-report.txt`（最近一次离线和联机结果）
- README 与 docs 的交付副本

## 7. 后续真机写测试前置条件

每个写测试都必须由用户单独授权，且先保存当前配置基线。建议顺序：

1. Wi-Fi SSID 原值回写。
2. 网络制式原值回写。
3. SIM 当前卡位原值回写。
4. 小区锁当前服务小区原值锁定/解锁。
5. 重启后的恢复检测。

固件升级和恢复出厂不纳入普通写测试。
