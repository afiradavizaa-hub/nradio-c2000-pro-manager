# NRadio 管理器 · 功能覆盖与验证状态表

> 状态含义：
> **真机验证** = 已在用户的真实设备上执行并核对结果；
> **已实现未验证** = 代码与接口载荷已就绪，但执行会改变设备状态（断网/换卡/改密码等），未在真机上执行；
> **只读** = 只展示设备真实数据，不提供写入入口（附原因）；
> **未实现** = 明确不做，并说明原因。

## 二、已实现，但未在真机执行（执行会改变设备状态）

| 功能 | 接口 | 不执行的原因 | 界面保护 |
|---|---|---|---|
| 拨号 / 断开 | `wan_set: connect_disconnect` | 会中断当前上网 | 按钮明确提示会断网 |
| 连接模式、漫游禁拨 | `wan_set` | 影响自动拨号行为 | 提示会重新拨号 |
| APN 配置增删改 | `wan_set: profile_list` | 整表下发，写错会影响用户流量套餐 | 提示"填写完整后再下发" |
| LAN 地址 / DHCP 池 / DNS / IPv6 | `lan_set` | 改 LAN 地址会导致需要用新地址重连 | 保存前做 IPv4 与范围校验，并提示后果 |
| 强制门户重定向（原厂无页面） | `lan_set` | 影响局域网终端上网行为 | 提示先在局域网内验证 |
| 静态 IP 绑定增删 | `lan_set: Fixed_IP_list` | 影响指定终端获取的地址 | 输入校验 |
| 在线终端拉黑 / 解除 | `device_management_set: action=2/3` | 会切断用户设备上网 | 二次确认弹窗 |
| 重置设备统计 | `device_management_set: action=4` | 清空累计统计 | 二次确认弹窗 |
| 修改管理员密码 | `account_management_set` | 改错会导致用户无法登录 | 需先输入当前密码，长度校验 |
| SIM / eSIM 卡位切换 | `mss_support_set` | 会重新注册网络，可能中断上网 | 明确标注"未经真机验证"，二次确认 |
| 重启路由器 | `device_restart` | 中断全部连接约 30–60 秒 | 二次确认 + 恢复提示 |
| 恢复出厂 | `device_restore_factory` | 清除全部配置 | 两次确认 |

## 三、只读展示（附原因）

| 功能 | 接口 | 只读原因 |
|---|---|---|
| MAC 黑白名单 | `wlan_mac_filters_info/set` | 设备当前返回的 allow_list / deny_list 均为空数组，条目字段结构无法确认；原厂界面也无此页面。写入行为未经真机验证，故不提供入口（避免下发错误配置）。 |
| WPS | `wlan_wps_info` + `wlan_security_set: connect_method` | 原厂前端未标注 connect_method 的取值语义（1/2/3），未经真机验证。 |
| 自定义防火墙规则 | `custom_fw_info/set` | 规则对象字段结构未知（设备返回空数组），构造错误规则可能影响转发。 |
| Wi-Fi 带宽 | `wlan_info.bandwidth` / `bandwidth_acs` | 原厂界面没有带宽选项，取值语义无法从设备侧确认，故只展示真实值。 |
| 工程模式信号数值 | `engineering_info` | 设备返回的是基带原始编码值（非 dBm），原厂页面也原样显示；本软件不擅自换算，只标注其为原始值，避免给出误导性结论。 |

## 四、未实现（明确说明）

| 功能 | 原因 |
|---|---|
| 固件升级 | 需通过 `/xml_action.cgi?Action=Upload&file=upgrade` 上传镜像；升级会擦写固件、失败可能导致设备无法启动，且本机没有可用固件包可供验证，无法验证也无法回滚，故不提供。 |
| 短信 / USSD / 电话本 | **该固件不包含这些模块**：原厂页面对应的 `html/sms/*`、`html/ussd/*`、`html/phoneBook/*` 全部返回 HTTP 404，且代码中不存在任何短信类接口。设备的 `status_info.new_sms_num` 字段恒为 0。第三方软件不应伪造这些模块。 |
| 账号新增 / 删除 | 原厂 `account_action` 的完整取值语义（新增、修改、删除的分支）未能从前端完全确认，乱下发可能导致账号表异常。仅实现"修改当前管理员密码"。 |
| 定时任务 / 计划重启 | 设备接口中不存在对应能力。 |

## 六、设备侧安全发现（实测）

对 `http://192.168.1.1` 的三组对照实验（原始 HTTP 请求，非软件逻辑）：

| 实验 | 结果 |
|---|---|
| 不带任何 `Authorization` 头请求 `xml_action.cgi` 读取状态 | **成功返回完整数据** |
| 携带伪造摘要（nonce/response 全为假值）请求同一接口 | **成功返回完整数据** |
| 使用错误密码完成登录流程 | 登录返回 200，之后读写请求同样可用 |

结论：该固件对 `/xml_action.cgi` **未真正校验登录凭据**，属于设备自身的安全缺陷，第三方软件无法修复。
本软件的做法是：照常要求凭据（与原厂流程一致），同时在软件内实际探测并**如实告警**，不掩盖这一事实。
