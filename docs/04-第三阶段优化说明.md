# 第三阶段优化说明（磁贴交互 / 图表 / 对比度 / 视觉系统）

## 一、磁贴互相遮挡：根因与修复

**根因（已定位，不是猜测）**：上一版 `TileGrid` 用「游标顺序推进」排布磁贴——只记录当前列/行，
遇到放不下就换行。这种算法**不检查跨行磁贴已经占用的格子**。
默认布局里 `device-info`、`status-summary`、`signal` 都是 `RowSpan=2`，
它们占住第 0–1 行之后，下一个 `ColumnSpan=4` 的磁贴只判断"当前列放不下"，于是被放到第 1 行第 0 列——
正好落在前面三块跨行磁贴的身体里，形成大面积重叠。

**修复**：改成**占用位图 + 首次适配装箱**。为每块磁贴扫描「第一个能完整容纳其 span×rowSpan 的空位」，
放置后把占用格子全部标记。这样跨行磁贴占用的区域不会被打穿，任何顺序、任何尺寸组合都不会重叠。

同时做了三处配套加固：

1. **行高按内容自适应**：先无高度约束测量一遍，取每行所需高度的最大值作为行高（下限 92px）。
   这解决了第二个隐患——WPF 默认**不裁剪**超出布局矩形的子元素，内容比磁贴高时会画到邻居身上。
2. 磁贴外层加 `ClipToBounds`，即使未来某个控件测量异常也不会越界绘制。
3. 排序/尺寸变化后重新装箱，窗口缩放、最大化、不同 DPI 都走同一条测量-排布路径。

**自动化验证（这是关键证据）**：自检脚本用真实数据渲染概览页，取出磁贴面板里每块的实际排布矩形，
逐对求交集。修复前输出正是用户看到的现象：

```
FAIL  磁贴布局问题：磁贴0 与 磁贴3 重叠 626x169；磁贴1 与 磁贴3 重叠 307x169；
磁贴3 与 磁贴4 重叠 944x169；磁贴4 与 磁贴5 重叠 626x105 …
```

修复后：

```
PASS  磁贴布局无重叠：8 块，网格 1263×1469，最小 207px / 最大 361px
```

## 二、长按拖动（手机桌面式状态机）

```
静止 →(按下)→ 轻按反馈(缩至 0.97) →(500ms 未移动)→ 进入编辑：全部磁贴轻微摇摆 + 可直接拖动
                              └→(移动>12px 或松开)→ 取消，不影响磁贴内按钮/图表点击
编辑 → 拖动：被拖磁贴浮起(1.04 + 阴影)、其他磁贴平滑避让、目标位置实时换位
      → 松开：动画归位、保存布局、继续摇摆
编辑 → 退出：点「完成」按钮 / 点空白处 / 离开页面 / 控件卸载 → 立即停止摇摆并保存
```

实现要点：

- **长按用 `DispatcherTimer` 单次触发**，触发后立刻停表；移动超阈值、松开、退出编辑、控件卸载都会取消并停表，
  不残留后台定时器（满足"动画可取消、无残留任务"）。
- **摇摆**：`DoubleAnimationUsingKeyFrames` 驱动每块磁贴的 `RotateTransform.Angle`，幅度 ±0.75°、
  周期 180ms、`SineEase` 缓动、每块错开 40ms 相位，形成自然的不同步摇摆；
  退出时 `Storyboard.Stop()` 并把角度归零。设置中心关闭动画后直接不启动。
- **平滑避让**：排布位置变化时，给该磁贴的 `TranslateTransform` 做 170ms 的位移补间（从旧位置到新位置），
  所以换位是滑过去的而不是瞬间跳。
- **按需求区分交互**：长按只在按下点不属于 Button/输入框/下拉框/滑块时启动，
  因此磁贴里的按钮、柱状图点击、下拉选择都不会误触发拖动。
- 未使用绝对定位、Z 轴堆叠或提 ZIndex 来掩盖布局问题；拖动时提 ZIndex 仅用于浮起视觉，布局仍由网格计算。

## 三、图表图例与提示重叠

`BarChart` 原来把图例和鼠标提示画在同一行（`h-22`），文字一长就压在一起。

现在：绘图区高度收窄 22px 留出**独立的图例带**，图例固定左下角；
鼠标提示改为**跟随光标的浮动卡片**——按内容自适应宽高，默认显示在柱子上方，上方空间不足自动翻到下方，
并始终夹在控件边界内；卡片使用主题的 `BgElevated` 背景 + 边框 + 圆角，显示时间、下载、上传、合计与数据口径。
坐标轴标签位于 `plot.Bottom+6`，与图例带互不侵占。窗口缩放、深浅主题切换后依然成立。

## 四、下拉框对比度（浅色主题白底浅字）

**根因**：WPF 默认 `ComboBox` 模板忽略自定义的 `Background`/`Foreground`，
弹出层用系统配色——浅色主题下就出现"白底 + 浅色文字"，深色主题下弹出层又不跟随主题。

**修复**：写完整自定义模板（控件本体 / 箭头 / `Popup` 弹出层三部分全部用主题资源绘制）：

- 弹出层背景 `B.Surface`、边框 `B.Border`、圆角与阴影统一，选中项 `B.AccentSoft`、悬停 `B.SurfaceHover`、禁用 `B.TextFaint`。
- 文字与背景对比：深色主题 `#E6EDF3` on `#161D26` ≈ 13.6:1；浅色主题 `#1B2430` on `#FFFFFF` ≈ 14.9:1，
  均高于 WCAG 2.2 AA 的 4.5:1（选中态 `AccentSoft` 上的正文同样超过 12:1）。
- 所有页面共用同一套样式，没有逐控件零散设色。

## 六、新功能调查（本轮只做可行性，未落地）

对照原厂后台与现有实现，找到 4 项有真实依据的候选：

| 候选 | 数据来源（已核实） | 价值 | 成本 | 本轮状态 |
|---|---|---|---|---|
| **路由器配置备份 / 恢复** | 原厂 `base.js` 中真实存在：下载 `GET /login.cgi?Action=Download&file=<配置>`（Digest，HA2 用 `/cgi/protected.cgi`）；恢复 `GET /xml_action.cgi?Action=Upload&file=backfile&config_backup=` | 高（换机/刷机前保命） | 中（需处理二进制下载与恢复前的强确认） | **未实现**：下载可用原始请求验证，但恢复一旦写错会让设备配置全丢，需要先在真机上完整验证双向流程后再开放 |
| **LTE 小区变化记录与信号告警** | `engineering_info`（ECGI/eNB/Cell_ID/PCI/EARFCN + RSRP/RSRQ/SINR），当前已每轮读取 | 中高（判断"是不是基站变了导致变慢"） | 低（本地记录差分即可） | **未实现**：已具备数据与轮询，缺的是记录表与 UI |
| **终端流量排名 / 异常增长提醒** | 本地采样历史（`TrafficHistory`）已按终端按日归档 | 中 | 低 | **未实现** |
| **终端连接 / 断连记录** | 设备不提供；只能由软件对比 `client_list` 差分得到 | 中 | 低（须明确标注为本地观测） | **未实现** |

其余原厂能力（短信/USSD/电话本、DNS 与连接日志、流量分类）已确认设备不提供，不做。

**为什么本轮没做**：本轮预算优先保证"修掉真实的坏掉的交互"（磁贴重叠、拖动、图表重叠、对比度），
这些是用户直接可见的问题；新功能留到下一轮，按上表优先级从"配置备份""小区变化记录"开始。
这份清单里每一条都能指到具体接口，不存在凭空设想。

## 八、未完成 / 待确认

1. 上文第六节的 4 项新功能均未实现（原因与优先级已列明）。
2. 摇摆与拖动动画是视觉交互，**没有自动化测试**，只做了代码级状态机梳理与"无残留定时器"的检查；
