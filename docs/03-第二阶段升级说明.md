## 一、白边问题的定位与修复

**真实原因**：软件是深色界面，但窗口的非客户区（标题栏、1 像素窗口边框、客户区外底色）仍由 Windows 按系统主题绘制。
系统处于浅色主题时，这一圈就是白的 —— 表现为窗口四周明显的大白边，与 WPF 内容无关。

**修复方式**（未使用透明窗口或自绘边框掩盖问题）：

- 调用 DWM API：`DWMWA_USE_IMMERSIVE_DARK_MODE`(20) 启用深色标题栏；
- `DWMWA_CAPTION_COLOR`(35) / `DWMWA_BORDER_COLOR`(34) 把标题栏与边框颜色对齐到软件背景色。
- 关键点：**保持原生窗口**，拖动、缩放、最小化、最大化、关闭全部是系统行为，未做任何自定义 chrome 替换。
- 主题切换时重新应用一次（深色主题用深色标题栏，浅色主题用浅色）。

代码：`Infrastructure/WindowChromeHelper.cs`，由 `MainWindow.ApplyChrome()` 在窗口初始化与主题变更时调用。

**验证**：浅色系统主题下启动，窗口边缘与标题栏与软件背景同色，无白边；窗口缩放/拖动为原生行为（未改动）。

## 二、视觉重构

- 主题资源拆分：`Themes/Dark.xaml`、`Themes/Light.xaml`（色板）+ `Themes/Theme.xaml`（控件样式）。
- 所有颜色改用 `DynamicResource`，因此切换主题时全部页面、卡片、图表、输入框、下拉框、导航同步变化。
- 新增 iOS 风格组件：分段控件（`SegmentHost`/`SegmentItem`）、开关（`Switch`）、磁贴样式（`Tile`，圆角/内边距可调）。
- 统一了圆角、间距、字号层级、悬停/按下/禁用状态，并补齐空数据、加载、失败状态呈现。
- 界面缩放（0.85x–1.3x）用 `LayoutTransform` 实现真实布局缩放，不是位图放大。

**验证**：界面自检在浅色与深色两种主题下分别实例化并布局「概览」「设置」页，均通过且 0 绑定错误。

## 三、流量统计体系（核心功能）

### 3.1 设备能力（真机核实，决定实现边界）

| 数据 | 设备是否提供 | 结论 |
|---|---|---|
| 设备级累计 tx/rx | 有（`status_info.tx_byte_all/rx_byte_all`） | 直接使用 |
| 每终端累计 tx/rx | 有（`client_list[].rx/tx`） | 直接使用 |
| 每终端本月 | 有（`rxm/txm`） | 直接使用（设备口径） |
| 每终端近 3 日 | 有（`rx3/tx3`） | 直接使用并展示 |
| 小时级 / 日级历史 | **没有** | 只能本地采样 |
| DNS / 连接日志 / 流量分类 | **没有** | 判定为不可实现 |

### 3.2 实现方式

`Core/TrafficHistory.cs`：持久化的本地流量历史（`%APPDATA%\NRadioManager\traffic-history.json`）

- 由设备累计计数器做差写入当日与当小时桶；设备级与终端级分开记录。
- 计数器回绕/清零（设备重启、统计被重置）时丢弃该次差值，不做错误归属。
- 采样间隔超过 3 分钟（软件未运行）时不做归因，单独累计为「未采集量」，绝不摊派到某一天充数。
- 保留期限可配（默认 90 天）；小时级数据只保留近 7 天，避免文件无限增长。

### 3.3 三个统计视图

- **当日（默认）**：24 小时柱状图（本地采样），点击任一小时 → 该小时各终端明细。
- **近七天**：按天柱状图，点击某天 → 该天各终端明细。
- **本月**：按天柱状图 + 本地口径合计，同时展示设备口径本月与近 3 日计数器用于交叉核对。

图表（`Controls/BarChart.cs`，自研绘制）支持悬停显示下载/上传/合计、点击下钻明细；单位随设置自动适配。

### 3.4 总体流量卡片

累计下载 / 累计上传 / 累计合计（设备计数器）与当日下载/上传/合计（本地采样）分区显示，
并标注数据来源、统计周期、最后采样时间、本地覆盖范围与未采集量。

**验证**：联机自检读到「累计合计 2.71 GB · 当日 616.76 KB · 柱数 24」，
并且 `traffic-history.json` 真实落盘（`DeviceDaily: {2026-10-16: {rx:420339, tx:3249557}}`，含每终端 `OnePlus-15` 记录）。
首次运行时桶值为 0（只建立基线），随运行增长 —— 符合设计，没有编造历史。

## 四、设备自定义名称与设备流量详情

- 自定义名称以 MAC 为主键保存在 `device-names.json`，重启软件后保留；原始主机名、MAC、IP 不被覆盖，界面同时展示两者。
- IP 变化不影响识别与历史归属；名称变更立即同步到列表、统计明细与详情页（同一份历史数据，口径统一）。
- 详情面板展示：自定义名称、原始主机名、MAC、当前 IP、连接方式、在线状态，
  以及当日 / 近七天 / 本月（本地口径）/ 本月（设备口径）四组流量与近七天趋势图。
- 设备在下次刷新中消失（离线）时自动关闭详情，避免展示过期数据。

**验证**：联机自检中列表解析到 `OnePlus-15`、`DESKTOP-U3444TP` 两台真实终端；名称存储与读取由 `DeviceAliases` 负责，保存后立即可读。

## 五、实时速率图 与 访问去向（能力边界）

- **实时速率图**：保留并强化。数据源为设备累计计数器差分（不需要测速网站、不跑 Speedtest），
  与设备上报的瞬时值在界面分开展示。仅在能取到计数器时才绘制，采样频率受限（2–10 秒可配）。
- **访问去向**：未实现，原因是设备不提供数据。已核查全部 30 个接口，没有 DNS 查询记录、连接日志或流量分类。
  本软件不会为此抓包、注入代理或安装常驻服务（那会记录用户全部上网行为，与要求冲突）。
  界面上（设备与流量页）明确写出了这一结论，而不是显示一个编造的「域名排行」。

## 六、磁贴式仪表盘

- 概览页改为 8 个磁贴：总体流量、流量统计、实时速率、连接状态、信号强度、设备信息、信号趋势、移动网络。
- `Controls/TileGrid.cs`：4 列网格面板，支持跨列/跨行尺寸；鼠标拖动磁贴即可调整顺序，
  拖动时磁贴半透明 + 强调色边框作为反馈；松开后立即持久化。
- 编辑模式（「编辑磁贴」按钮）下每个磁贴提供加号/减号（尺寸）与「标题」（显示开关）。
- 布局、磁贴外观、数据设置分开保存；`TileLayout.Merge()` 在版本升级时保留用户布局并补上新增磁贴，
  未知磁贴被忽略、越界尺寸被收敛到允许范围。

**验证**：自检中执行 `MoveTile(0→2)` 后断言「界面顺序 == 持久化顺序」→ 通过（`PASS 磁贴拖动排序逻辑与持久化一致`）并已复原。

## 八、性能与稳定性

- 未新增任何第三方依赖、常驻进程或后台服务；不默认开机自启。
- 请求均有超时、取消与限次重试；轮询有重入保护（上一轮未完成则跳过），最小化时可暂停。
- 曲线采样采用有界缓存（600 点）、小时级历史仅保留 7 天、日志上限 500 条。
- 历史落盘每 12 个轮询周期一次，避免高频 IO。
