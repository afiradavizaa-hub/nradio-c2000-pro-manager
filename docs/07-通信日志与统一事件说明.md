# 通信日志持久化与统一事件（v3.3）

## 1. 根因

### 1.1 日志关闭后消失

旧 `Core/ActivityLog.cs` 只有一个 `ObservableCollection<LogItem>`：

- 没有打开、创建或追加任何日志文件；
- 软件退出时只保存设置和电池历史，没有刷新日志；
- 通知中心与通信日志是两个互不相干的出口，通知不会进入日志；
- 日志页的“清空日志”只清内存集合。

因此进程结束后所有记录必然消失，与保存路径或异步时机无关，属于“实现上从未落盘”。

### 1.2 日志页筛选会拖住 WPF 派发队列

第一版筛选使用 `ICollectionView.Refresh()`，并在 `ObservableCollection.CollectionChanged`
回调里直接调用。集合变化、筛选视图刷新和页面布局互相触发，脱离窗口布局的自检中会持续产生
渲染/布局工作，`Dispatcher` 无法进入空闲。现已改成独立的 `FilteredItems`：

- 新事件只在匹配筛选条件时做一次增量插入；
- 切换搜索/类别/级别时才重建筛选结果；
- 页面绑定普通 `ObservableCollection`，不在集合变更回调中刷新视图。

### 1.3 电池图表与历史

- 稀疏采样时旧悬停只在圆点 18 px 内命中，两个采样点之间大部分区域无法查看；
- 拖动可以进入未来或远超保留期的空时间区，没有统一边界；
- 断连标记会形成“有效点→断连点”“断连点→恢复点”两个相邻区间，旧统计把一次断连算两次；
- 分析器把状态未知的区间计入了放电时长；
- 电池历史保存没有串行化，退出保存可能与定时保存同时写临时文件；
- 采样时间只比较“是否前进”，没有拒绝明显超前的系统时间；
- 重连成功后旧的断连提示不会立即清除；
- 采样/保存失败没有进入统一日志。

## 2. 日志实现

文件：

```
%APPDATA%\NRadioManager\activity.log
%APPDATA%\NRadioManager\activity.1.log
%APPDATA%\NRadioManager\activity.2.log
%APPDATA%\NRadioManager\activity.3.log
```

每行一个 JSON 事件，字段为 `Time`、`Level`、`Category`、`Source`、`Message`、`Detail`。
目录不存在时自动创建；中文直接以 UTF-8 写入，便于人工查看。

写入机制：

1. 事件先做统一脱敏，再发布到页面集合、进入有界队列；
2. 同一时刻只有一个刷新任务，按入队顺序分批追加；
3. 单个写入块不超过配置上限，超过时先轮转；
4. 最多保留 3 个归档，并清理超过 30 天的文件；
5. 退出时 `Flush(3s)`，窗口关闭后仍可读取；
6. 写失败时事件放回队首、记录 `LastWriteError`、写 `activity-write-error.txt` 并显示界面通知；
7. 日志故障提示使用不写日志的通知路径，避免递归。

## 3. 统一事件类别

| 类别 | 典型事件 |
|---|---|
| 通知 | 所有 `NoticeCenter` 通知、告警、恢复及触发说明 |
| 连接 | 开始连接、登录成功/失败、认证失败、会话恢复失败、手动断开 |
| 设备 | 本地检测的上线/离线时间、`run_seconds` 回退判定 |
| 通信 | 请求失败、超时、会话重试、写请求、10 分钟节流的成功轮询 |
| 采样 | 电池采样开始/暂停、字段无效、状态变化、未来时间拒绝 |
| 网络 | 网络质量检测开始、结果、状态变化、失败原因 |
| 运行 | 软件启动/退出、未捕获异常、磁贴提示 |
| 配置 | 连接、轮询、电池采样间隔、保留期、主题、设置导入 |
| 数据 | 流量阈值、电池历史清理等数据事件 |
| 存储 | 设置、流量历史、电池历史、通信日志写入异常 |

高频控制：

- `status_info` 成功轮询按 10 分钟最多记录一次；
- 请求错误逐条记录，便于定位超时/重试，但断连后停止轮询；
- 电池采样仅在首个有效样本、可用性变化、充电状态变化时记录；
- 时间异常最多每 5 分钟记录一次；
- 网络质量检测本身最多每 5 分钟一次。

## 4. 验证

```powershell
dotnet build src\NRadioManager\NRadioManager.csproj -c Release
dotnet build tests\NRadioManager.SelfTest\SelfTest.csproj -c Release

# 离线 UI/绑定/图表/日志测试
NRadioManager.exe --ui-smoke

# 两个独立进程验证写入、退出、重新加载与脱敏
SelfTest.exe --log-persistence-write <临时目录>
SelfTest.exe --log-persistence-read <临时目录>
```

已覆盖：有数据/无数据/单点/缺口/断连/重启、四档时间范围、悬停/平移/缩放/复位、
历史并发保存与损坏恢复、日志轮转/保留期/损坏行/写入失败/通知统一入库/页面增量筛选。

未覆盖：本次没有重新连接真机，因此真机电池采样和真实断连/重启时序仍需在设备上复核。
