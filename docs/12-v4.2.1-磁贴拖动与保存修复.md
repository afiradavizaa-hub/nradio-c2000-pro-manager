# v4.2.1 磁贴拖动与保存修复

日期：2026-10-26

## 问题一：编辑后关闭软件，磁贴顺序未保留

### 原因

旧实现依赖鼠标捕获结束时调用保存。拖动过程中数据源会立即多次重排，导致容器重建并可能丢失鼠标捕获；
此时松手事件没有执行，内存中的界面顺序与 settings.json 中的旧顺序不一致，关闭后只保存旧配置。

另外，配置中任一浮点字段变成 `NaN` 或正负无穷时，System.Text.Json 会拒绝序列化整个文件，
导致同一轮所有设置都无法保存，但界面此前不一定能及时显示原因。

### 修复

- 关闭窗口前强制按当前界面集合顺序调用 `PersistTiles()`。
- `MainViewModel.Shutdown()` 再执行一次布局持久化，形成双重保障。
- 点击“完成”、退出编辑模式、正常松手和关闭窗口均能提交当前顺序。
- 保存前将异常的浮点配置恢复为安全默认值，避免一个无效数值阻断整份设置写入。

## 问题二：拖动一个磁贴时其他磁贴乱飘

### 新交互

1. 只在磁贴标题区域按住拖动，避免在图表或输入控件上误触。
2. 被拖磁贴跟随鼠标移动并提升显示层级。
3. 其他磁贴保持原位，不再在每个鼠标移动事件中重新装箱。
4. 目标落点显示虚线强调色框。
5. 松开鼠标后只重排一次，并立即保存。

## 验证

- 真实界面将第一个磁贴拖到第二个位置：拖动过程中其他磁贴保持不动。
- 保持编辑模式直接按 Alt+F4 关闭，重新启动后顺序仍为新顺序。
- 自动化 UI 自检新增并通过：
  - 拖动过程中顺序不变；
  - 松手后只提交一次；
  - settings.json 磁盘内容与界面顺序一致；
  - 重载后看到上次保存布局；
  - 配置写入失败不再被静默忽略。
